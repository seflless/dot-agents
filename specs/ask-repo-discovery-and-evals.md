# Ask Repo: Walkthroughs + Cursor Integration

## Problem (Revised)

Original hypothesis was that hardcoded tactics would beat Claude at repo analysis. **Testing showed this is false** - Claude Code already knows how to analyze repos effectively, even for unknown codebases.

**New insight:** The skill's value is NOT faster analysis. It's:
1. **Local storage** - Repos in `~/.ask-repo/` for user exploration
2. **Generated walkthroughs** - Markdown files with code snippets, saved IN the repo
3. **Cursor integration** - Open at specific file:line

## Core Value Proposition

| What | Why |
|------|-----|
| Clone to `~/.ask-repo/` | User can explore, follow-up questions are fast |
| Markdown walkthrough with snippets | See code inline without jumping |
| Save walkthrough IN repo | Relative links work in Cursor |
| Open in Cursor at file:line | Jump directly to relevant code |

## Workflow

```
User: "How does zustand manage state?"

1. CONCURRENT
   ├── Start answering (from knowledge)
   └── Clone to ~/.ask-repo/pmndrs-zustand/ (background)

2. Answer with code snippets inline

3. Save walkthrough:
   ~/.ask-repo/pmndrs-zustand/WALKTHROUGHS/state-management.md

4. Offer Cursor:
   cursor ~/.ask-repo/pmndrs-zustand --goto src/vanilla.ts:60
```

## Walkthrough Format

```markdown
# How zustand manages state

> Generated by ask-repo on 2024-01-15

## Key Files
- [src/vanilla.ts](../src/vanilla.ts) - Core store logic
- [src/react.ts](../src/react.ts) - React bindings

## Walkthrough

### Store Creation

The store is a simple closure:

\`\`\`typescript
// src/vanilla.ts:60-75
const createStoreImpl = (createState) => {
  let state
  const listeners = new Set()
  // ...
}
\`\`\`

### React Integration

Uses `useSyncExternalStore`:

\`\`\`typescript
// src/react.ts:26-37
export function useStore(api, selector = identity) {
  return useSyncExternalStore(api.subscribe, ...)
}
\`\`\`
```

## Discovery Mode

Still useful for finding repos:

```bash
scripts/discover.sh "react state management"
```

Returns top repos by stars, user picks one to analyze.

## Key Finding: Skills Cannot Enforce Workflows

**Problem discovered during testing:**

Even with explicit instructions like "DO NOT analyze the repo yourself. ONLY run this command", the LLM ignores the skill instructions and does its own analysis. This is because:

1. Skills are **instructions**, not **constraints**
2. LLMs can ignore instructions when they think they "know better"
3. The LLM sees the repo is already cloned and decides to analyze directly

**Attempted solutions that failed:**
- Explicit "MANDATORY" sections
- "DO NOT skip this step" warnings
- "You MUST use the Bash tool" instructions
- Minimal skill with only one instruction

**Solution that works: Wrapper Script**

```bash
scripts/ask-repo.sh "<github-url>" "<question>"
```

This script:
1. Clones the repo (deterministic)
2. Calls Claude for analysis (LLM does what it's good at)
3. Saves output to WALKTHROUGHS/ (deterministic)
4. Outputs Cursor commands (deterministic)

**Conclusion:** The reliable path is to use the wrapper script directly, not rely on skill instructions. Skills can suggest the wrapper, but users or automation should call it directly.
